# Principal UI/UX аудит (мобильный): сводка находок F1–F16

Состояние на 2026-11-18. Короткая сохраняемая в репозитории сводка этапа A аудита Claude Opus. Исполнение разделено на три Issue: [#118][i118] (этот пакет), [#119][i119] и [#120][i120]. Документ создан в рамках AC-6 Issue #118.

## Как читать сводку

- **Источник.** Исходный отчёт Opus и его скриншоты в репозитории не хранятся. Сводка собрана из текста Issues #118–#120; детали сверх этого текста здесь **не восстанавливались**. Временные локальные скриншоты не считаются доказательствами.
- **Признак проверки.**
  - **V** — визуально подтверждено Opus в эмуляции мобильного Chromium (не реальное устройство).
  - **V\*** — наблюдалось в Chromium с искусственной задержкой запроса.
  - **C** — найдено чтением кода, на экране не подтверждалось.
- **Приоритет** — приоритет пакета (Issue); приоритеты отдельных находок внутри пакета в источниках не записаны.

## Что делает этот пакет (#118)

| № | Изменение | Где |
| --- | --- | --- |
| F1 | «Завершить» — `contained primary`, «Отменить попытку» — `outlined error` с рамкой 2 px; кнопки подтверждения, просмотра результата и повторной отправки получили `minHeight: 48`; на xs кнопки идут друг под другом на всю ширину | `AttemptSubmissionControls.tsx` |
| F2 | Prev/Next делят строку поровну и не ниже 48 px на xs, на md+ остаются обычными; «Пройти заново» не ниже 48 px | `PracticeSet.tsx`, `LesenScreen.tsx`, `AttemptReviewView.tsx` |
| F7 | Фокус переходит на заголовок подтверждения и возвращается на исходную кнопку после отказа | `AttemptSubmissionControls.tsx` |
| F8 | Отдельные нейтральные `role="status"` для `cancel-loading` («Получаем состояние попытки…») и `cancelling` («Отменяем попытку…»); Alert и повтор при `cancel-failed` и `cancel-uncertain` сохранены | `AttemptSubmissionControls.tsx`, `messages/{en,ru}.json` |

Не менялись: `useAttemptSubmission.ts`, серверные операции, база, подсчёт результата, сроки, правило прямой сдачи при нуле пропусков.

## Что проверено и что нет

| Проверка | Статус |
| --- | --- |
| Vitest: размеры (`min-height: 48px`), классы кнопок, статусы и Alert, EN/RU | выполнено локально |
| Playwright на изолированном стеке `b1-kompass-e2e`: размеры в браузере, 320/360 px, EN/RU, переполнение, фокус, команды submit/cancel | выполнено локально (`npm run e2e:test -- --build`, Chromium-эмуляция): 447 из 447 |
| CI `Quality` на head PR | проверяется в PR |
| Реальные iPhone Safari и Android Chrome, 320/360/390 px, EN/RU | **NOT VERIFIED** |
| Скринридер (VoiceOver, TalkBack): объявление статусов и заголовка подтверждения | **NOT VERIFIED** |
| Реальный submit и cancel на устройстве владельца | **NOT VERIFIED** |
| Подтверждение приёмки владельцем | **NOT VERIFIED** |

Эмуляция Chromium (в том числе вьюпорты Playwright) не заменяет проверку на реальных устройствах: она не воспроизводит экранную клавиатуру, динамическую панель адреса Safari, жесты и скринридеры.

## Вне этого пакета

- Решение «подтверждать сдачу даже при нуле пропусков» — отдельное продуктовое решение владельца; правило прямой сдачи не изменено.
- Закрытые #62, #105, #111 не переделывались; видимость submitted в библиотеке — #99.
