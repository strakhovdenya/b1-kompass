## Как читать отчёт

Четыре состояния ведутся раздельно; одно не подтверждает другое.

| Состояние | Что означает | Источник доказательства |
| --- | --- | --- |
| Реализовано | Код и миграции в `main` | Слитый PR |
| CI проверено | Required check `Quality` зелёный на конкретном SHA | Run `CI` на этом SHA |
| Развёрнуто | Версия выложена в именованное окружение | Run `Release Production` и GitHub Deployment |
| Принято владельцем | Владелец выполнил ручную проверку на настоящем материале, устройствах и в облаке | Запись владельца с датой (в этом отчёте её нет) |

Статусы: **PASS** — подтверждено доказательством, названным в строке; **PENDING** — проверка не выполнена или зависит от действия владельца; **FAIL** — проверка нашла дефект (нет); **n/a** — для строки такой проверки не существует. Наличие файла теста, закрытый Issue или слитый PR PASS не дают.

## Расхождения и ограничения

- Недоступный режим в UI (AC-02, PENDING): полный экзамен без подтверждённого профиля — отключённая карточка с подписью «Coming soon.»; блок на время всегда выбираем, без профиля сервер отвечает `not-enabled`, UI показывает «This mode is not available yet.». Причина («неполный материал» / «профиль не подтверждён») не называется; тексты подписей автотестом не проверяются.
- Подписанный URL Storage, уже выданный, живёт до своего TTL; закрытие Hören блокирует только новые выдачи (AC-29).
- Названия Vitest-тестов в CI-логе не перечислены по одному; доказан проход файла.
- PRD и PLAN M2 сохраняют статус Draft; это источники требований, а не описание кода. Они в этой задаче не менялись.
- Drafts M3 ([PRD-admin-exam-library.md](prd/PRD-admin-exam-library.md)) не одобрен и не реализован; библиотека, второй экзамен и универсальный импорт в M2 отсутствуют.
- Корневой `README.md` и `docs/m1-acceptance.md` не изменялись по границе задачи.

3. Выполнить облачные проверки M-15, M-16, M-18 по процедуре в `docs/deployment.md`.
4. Решить судьбу M1 AC (⏳) отдельной записью в `m1-acceptance.md`; эта задача её не заменяет.
